# Joy-Con 2 Boat Game

Joy-Con 2を実際のオールのように前後へ動かし、ボートを操作するUnreal Engine 5製のゲームです。

一般的なスティック操作ではなく、Joy-Con 2に搭載されたマウスセンサーから取得した動きをゲームへの入力として利用し、実際に左右のオールを漕ぐような操作感を目指して制作しました。

## 特徴

* Joy-Con 2を前後に動かしてボートを操作
* 左右のJoy-Con 2を独立した入力として取得
* 両手の入力から前進・後退・左右旋回を判定
* Joy-Con 2のマウスセンサー入力をゲーム操作用の値へ変換
* PythonとUnreal Engine 5間でUDP通信を行い入力値を送受信
* Unreal Engine 5側のボート制御をC++で実装

## 操作方法

| Joy-Con 2の操作 | ボートの動作 |
| ------------ | ------ |
| 左右両方を引く      | 前進     |
| 左右両方を押す      | 後退     |
| 左側を引く        | 右旋回    |
| 右側を引く        | 左旋回    |

左右の入力を別々に取得することで、2本のオールを使ってボートを操作する感覚を再現しています。

## システム構成

```text
Joy-Con 2（左・右）
        ↓
Joy2Win
        ↓
マウスセンサー入力取得
        ↓
左右それぞれの移動量を算出
        ↓
デッドゾーン・入力保持などの補正
        ↓
ゲーム用入力値へ変換
        ↓
UDP通信
        ↓
Unreal Engine 5
        ↓
左右入力の合計・差を計算
        ↓
前進 / 後退 / 左右旋回
        ↓
ボート移動
```

Joy2Win側では、Joy-Con 2のセンサーから取得した値をそのまま使用するのではなく、ゲーム側で扱いやすい入力値へ変換しています。

変換した左右の入力値をUDPでUnreal Engine 5へ送信し、UE5側のC++コンポーネントで受信してボート操作へ使用しています。

また、Joy2Winの既存機能との互換性を維持するため、左右の入力値はvJoyの個別軸にも反映しています。

# 主な実装

## 1. Joy-Con 2の左右入力取得

左右のJoy-Con 2をそれぞれ独立した入力デバイスとして扱い、マウスセンサーからY方向の移動値を取得しています。

現在値と前回値との差分を求めることで、

* Joy-Con 2を前方向へ動かした
* Joy-Con 2を後方向へ動かした

という操作を判定できるようにしました。

左右を別々に処理することで、片側だけを動かした場合にも対応しています。

---

## 2. センサー入力の補正

センサーから取得した値をそのままゲームに使用すると、小さな入力の揺れや高速な入力を安定して取得できない問題がありました。

そのため、以下の処理を追加しています。

* 小さな入力を無視するデッドゾーン処理
* センサー値の急激な変化への対応
* 入力を短時間保持する処理
* 入力値の上限・下限の制限
* ゲームで扱いやすい `-1.0 ～ 1.0` の範囲への変換

Joy-Con 2側の入力更新とUE5側のゲームフレームの更新速度が異なるため、短時間の入力がUE5側で取得されない場合がありました。

そこで、検出した入力を一定時間保持することで、素早くJoy-Con 2を動かした場合でもゲーム側で入力を取得しやすくしています。

---

## 3. UDPによるUnreal Engine 5との連携

Python側で変換した左右の入力をUDP通信でUnreal Engine 5へ送信しています。

送信する値は、

```text
左Joy-Con 2の入力値,右Joy-Con 2の入力値
```

という2つの値です。

Unreal Engine 5側では専用のC++コンポーネントを実装し、UDPパケットを受信します。

受信した値を左右それぞれ `-1.0 ～ 1.0` の範囲へ制限し、ボート操作処理へ渡しています。

一定時間データを受信できなかった場合は入力値を0へ戻すことで、通信が途切れた際にボートが動き続けないようにしています。

---

## 4. ボートの前進・後退・旋回

左右のJoy-Con 2から取得した入力を使用して、ボートの推進力と旋回量を算出しています。

### 前進・後退

左右の入力の平均値を使用して、ボートの前後方向への入力を求めています。

両方を同じ方向へ動かした場合、

```text
左右の入力
    ↓
平均値
    ↓
前進 / 後退
```

としてボートへ反映します。

### 左右旋回

左右の入力値の差を使用して旋回入力を求めています。

```text
左入力 - 右入力
        ↓
旋回入力
```

とすることで、

```text
左側だけを引く → 右旋回
右側だけを引く → 左旋回
```

という、実際の手漕ぎボートに近い操作方法を実現しています。

---

## 5. ボートの移動処理

ボートの前後移動と旋回はUnreal Engine 5のC++側で処理しています。

単純に位置を一定量変更するのではなく、

* 前進・後退の加速度
* 漕いだ際の加速
* 旋回加速度
* 前後方向の水抵抗
* 回転方向の水抵抗
* 前進・後退の最高速度
* 最大旋回速度

を使用して速度を計算しています。

入力を止めた瞬間にボートが完全停止するのではなく、徐々に減速させることで、水上を進むボートらしい挙動を意識しました。

また、移動時には衝突判定を行い、障害物へ衝突した際の処理も行っています。

---

## 6. 水面への追従

Unreal Engine 5のWater Systemから水面情報を取得し、ボートの複数箇所から水面の位置や法線を参照する処理を実装しています。

ボートのコリジョンを基準として前後左右に判定点を配置することで、使用するボートモデルのPivotやMeshの状態だけに依存しない構成にしています。

# Joy2Winの改変について

Joy-Con 2をWindows上で利用するため、OSSの「Joy2Win」を利用しています。

本作品ではJoy2Winをそのまま使用するのではなく、Joy-Con 2をボートのオールとして利用するための処理を一部追加・変更しました。

主な変更内容は以下です。

* 左右のJoy-Con 2のマウスセンサー入力を個別に取得
* センサー座標から移動差分を算出
* 小さな入力を除外するデッドゾーン処理
* UE5側で入力を取得しやすくする入力保持処理
* 左右の入力をvJoyの別々の軸へ設定
* 入力値を `-1.0 ～ 1.0` に変換
* 左右の入力値をUDPでUnreal Engine 5へ送信

既存OSSを利用するだけでなく、ソースコードを調査し、自分のゲームに必要な入力方式へ拡張しました。

# 工夫した点

## 実際の動きをゲーム操作へ変換

一般的なゲームパッドのスティックではなく、Joy-Con 2そのものを前後へ動かすことをゲーム操作へ結び付けました。

「ボタンを押す」のではなく「実際に漕ぐ」という身体動作を入力として使用することで、ゲーム内のボート操作との一致を意識しました。

## 左右の入力を独立して処理

左右のJoy-Con 2を1つの入力として扱うのではなく、それぞれ別々の値として取得しています。

これにより、

```text
両方を動かす
→ 前進・後退

片方だけを動かす
→ 左右旋回
```

という操作を同じ入力システムから実現しました。

## 異なる技術間の連携

本作品では、

```text
Joy-Con 2
Python
Joy2Win
vJoy
UDP
Unreal Engine 5
C++
```

と複数の技術を組み合わせています。

Joy-Con 2からセンサー値を取得するだけで終わらせず、その値をゲーム向けに加工し、UE5まで送信して実際のゲーム操作として利用できるところまで一連のシステムとして実装しました。

# リポジトリについて

本作品では第三者制作のゲームアセットを使用しています。

そのため、ライセンス上の理由からゲームプロジェクト全体は公開せず、本リポジトリには自身が実装・変更した公開可能なソースコードを中心に掲載しています。

主な内容は以下です。

```text
Boat_Submission/
├─ Source/
│  └─ Boat/
│     ├─ BasePlayer.cpp / .h
│     └─ JoyConUdpReceiverComponent.cpp / .h
│
└─ JoyCon2Input/
   ├─ control_type/
   │  ├─ duo_joycon.py
   │  └─ duo_joycon_original.py
   │
   └─ Joy2Win関連ファイル
```

`duo_joycon_original.py` と変更後の `duo_joycon.py` を比較することで、Joy2Winに対して変更した部分を確認できるようにしています。

# 総括

本制作では、Joy-Con 2という入力デバイスとUnreal Engine 5を連携させ、実際の身体動作をゲーム操作へ変換するシステムの制作に取り組みました。

特に、センサーから取得した値をそのまま利用するのではなく、差分計算、デッドゾーン、入力保持、数値変換などを行い、ゲームで安定して利用できる入力へ変換する部分を工夫しました。

また、既存OSSのソースコードを調査して必要な機能を追加し、PythonとC++をUDP通信で接続することで、入力取得からゲーム内のボート制御までを一連の仕組みとして実装しました。

この制作を通して、既存技術を調査して目的に合わせて拡張することと、複数の技術を組み合わせて問題を解決する経験を得ました。
